Hello Guy, 


I'm not sure why 3.9.10 would be having problems on a new VM, as I'm not familiar with your install at this point, unfortuantely.


As for the location of the HSQL database - all database configuration information should be found in, or pointed to from, a database*.properties file in $GP_HOME/resources.


The default file from the last 3.9.10 release (patch 0.5.2) looked like this.  If I didn't already know the database configuration of a GenePattern server, that is where I would start looking. Additionally, assuming you are using the default HSQL database from that release,  the database files should be found in that same location.


You should be able to query your database either from an external tool (using the information in the properties file to connect) or via the <your_server_url>/gp/sql.jsp page (which is accessible only by admin-level users, unless you have configured that differently)


Please let us know if that helps at all.


Best always,

Hello Guy, 


As I suspected there are a few things you might be able to do, but unless you had backups of the filesystem and the database from before the replacement, you are a little bit out of luck.


Here's a more detailed response from our team software architect, Ted Liefeld:


"The [database] contents are stored in that file so they may want to check for a recent backup that has the contents.  But if their current copy has modules that are not there but missing users that makes no sense unless they were deleting modules.  I would expect either no modules and no users (for a blank database) or modules and users but modules not running if the tasklib dir was also deleted.  So it's odd that they have modules there "but missing" unless they mean just a few of the last-added modules.


As for recovery, if they have backups of the resources, jobResults, users, and tasklib directories (all from the same time point) that is about the only thing that would work that did not require re-creating users and re-installing modules.  


If you delete your file system and database, and don't have backups, you won't have the contents of the file system and database."


Please let us know if we can do anything more to help.


All the best
-Barbara
