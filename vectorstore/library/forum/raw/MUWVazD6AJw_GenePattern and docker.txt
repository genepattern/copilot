I had the possibility to test a prerelease of the new GenePattern version. This uses docker to start modules. There I noted a problem : the docker demon runs as root. As a consequence some of the files created by GenePattern now belong to root rather than to the user who runs the GenePattern server. One consequence is that GenePattern cannot delete the jobs. Is there a solution for this (other than run GenePattern as root) ?

This is a known issue. We haven't come up with a workaround yet. To be clear, we have not spent a lot of time on this because we are focusing on the AWS integration. I will ask other members of the GP Team to chime in.

One possibility is to use Singularity; the FAQ suggests that root is not required to use a container. It is required to create a container, but that can be done as a one-time admin step for each module. This looks promising.

As a matter of fact, it's already in use on the production GP server at Indiana University (https://gp.indiana.edu/gp/). On this server we wrap a module in two steps:
    (1) pull the docker image into a singularity image on the local file system
    (2) edit the GP configuration to use the singularity command

On newer versions of GenePattern (>= v3.9.11), the customization is simple. You still have to manually create the image file. The rest is a simple update to the config_custom.yaml file. I am happy to offer the details if and/or when you are ready to use Singularity.

Regards,
Peter
