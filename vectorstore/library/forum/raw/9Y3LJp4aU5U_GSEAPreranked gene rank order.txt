Hi Roberto,

 

This kind of ordered list isn't really what we'd expect to accept for GSEA Preranked. Typically what we expect here would be a descending order ranking where the values span positive and negative, so something more like a Log2(FC) list. So I do think if you want to use this data, you would need to reverse the ranking order, and additionally I would suggest that perhaps you could apply the sign from the log2FC to get something more on the scale that we would expect (although you don't technically have to do this).

 

So your 1,2,3,4,5,6,8,9 (for the sake of example) list would, if 2,5,9 were a negative log2fc become 1,3,4,6,8,-9,-5,-2, and then to rescale them 5,4,3,2,1,-1,-2,-3 where the old #1 is now 5, #2=4, -9=-1 etc. Does that make sense?

 

Then for your data where the rank values aren't biologically meaningful, you would also want to change ethe "Enrichment Statistic" parameter from the "weighted' option to the "classic" option.

 

That is what I would try if I was working with this kind of data.

 

Let me know how that goes and if you experience any issues/anything doesn't look right with the results and we'll see what we can do.

 

-Anthony

Hi Roberto,

 

We recommend always specifying a CHIP platform when using MSigDB gene sets, even if your data is already in Human Gene Symbols. Over time the approved symbol for a gene can change and the chips we provide contain the historical mappings to convert an old symbol to the current (as of the release of that version of MSigDB) symbol. By specifying a CHIP it ensures that the gene symbols the software is testing are the same as the ones in the gene sets, otherwise any symbols that have changed would be dropped from the dataset.

Hi Roberto,

 

Our Ensembl chip file expects unversioned Ensembl gene ids (not transcript IDs) so these would be of the format ENSG00000123456, it is common for pipelines to produce versioned Ensembl IDs, (i.e. ENSG00000123456.7) that trailing version should be stripped from the IDs. But other than needing to remove the version, our MSigDB 7.5.1 chips are based on Ensembl Release 105 (Dec 2021) so it should work well if you've used that version or any version prior to 105. HGNC IDs (in the format HGNC:12345) would also work through the HGNC ID chip file.

 

We might also recommend changing the "Collapse Mode for Probe Sets >=1" from the default "max_probe" to the "sum_of_probes" option under Advanced Fields if running in standard GSEA and not GSEA Preranked.

 

Let me know if you have any issues with these options/settings.

 

-Anthony
