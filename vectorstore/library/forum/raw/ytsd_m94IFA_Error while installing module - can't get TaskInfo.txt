unfortunately we stopped testing with postgres more than 8 years ago (we are a small team and have limited resources) so it looks like the postgres support has code rotted.  We have a few options here depending on your priorities


1. We can try to cobble together a working postgres setup.  This will involve a bunch of trial and error.  You are missing at least one other table at a glance, and category_seq is a Sequence not a table, but there may be more of them missing as well. 


2. You can reinstall using a database we know will work.  HSQL for small/private deployment is the default when installing.  MySQL is what we use for our public sites.


3. If you go the HSQL route, you could use the dockerized server.


Let me know how you would like to proceed and I'll try to help along whichever path you choose.

Praveen,


since it looks like its not able to get a connection to the database, the first thing I would check is that the version of the JDBC driver and the database are compatible.  IIRC the default mysql jar file is mysql-connector-java-5.1.33-bin.jar.  Based on https://downloads.mysql.com/docs/connector-j-5.1-relnotes-en.a4.pdf it is only suitable for 

      Version 5.1.33 is a maintenance release of the production 5.1 branch. It is suitable for use with MySQL
      Server versions 5.5, and 5.6

Our production servers run against an AWS aurora db that is MySQL 5.7 api consistent (5.7.mysql_aurora.2.11.2).  Another of our servers runs using this connector against mysql:5.7.43 (running in docker). The newest mysql connector jar file seems to be 5.1.49 and it includes support up to mysql 8 though we haven't tested that with GenePattern.   


What version of MySQL were you running?


Hope this helps

As one more thing that might help, here is how we run the docker container for the server using mysql.  Note the inclusion og --lower_case_table_names=1 which is needed to ensure that table names can be case insensitive.



docker run --name gp-mysql -e MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD} -e MYSQL_USER=${MYSQL_USER} -e MYSQL_PASSWORD=${MYSQL_PASSWORD} -e MYSQL_DATABASE=${MYSQL_DATABASE}  -p 3306:3306 -p 33060:33060 -v ${DATADIR}:/var/lib/mysql  -d mysql:5.7.43 mysqld --lower_case_table_names=1
