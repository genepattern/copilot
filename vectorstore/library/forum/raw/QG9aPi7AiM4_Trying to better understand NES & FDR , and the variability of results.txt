Hi,

 

FDR is generated by creating an empirical null distribution by either permuting the samples (phenotype permutation – only valid with a sufficiently large number of samples) or by permuting the gene set (gene_set permutation) and testing enrichment against that null distribution. Gene set permutation constructs a random gene set of the same size from the genes in your input gene list.

 

Enrichment results will vary from run to run due to the seed being used in the random number generator that is used when constructing the random permutations. GSEA offers an advanced parameter that allows you to set the seed to a fixed value that will generate an identical permutation from run to run. There are various mathematical reasons why this is not set to a fixed value by default, but setting this seed should allow you to compare results from run to run.

 

You can either include your gene set in the run along with the other gene sets you wish to test, or you can set the seed and run it separately. Do be aware that you should make sure that the gene symbols used in your gene set match the Ensembl transcriptome version that was used to generate the version of MSigDB being used, which should also match the CHIP file you are using to collapse or remap your dataset. This step of symbol harmonization is important to ensure a consistent gene universe in the analysis.

Hi,

 

I’ve followed up on this with one of the original developers of the GSEA application, and yes, my understanding of the FDR calculation was incorrect. They had the following to say:

“Yes, the FDR depends on both: the entire distribution of observed gene sets scores and the entire distribution of reference (null) scores. Any change in those distributions could change the FDRs. On top of that, the FDR is a ratio so it is quite noisy in the tails of the distribution where we are more interested in those values. All this is expected. Because of this and other technical limitations of the statistics (p-values and FDRs) they need to be taken only as a rough estimate of how unexpected a given score is, but not as hard evidence for the significance of results. The best way to validate a result is to perform an independent experiment instead of crunching the number in different ways until a significant value pops out. In general, we can say that the use of FDRs makes sense when a large number of gene sets are been used, rather than one or a handful. This should be evident as FDR requires a distribution of observed values.“

 

It’s clear that we need to better document the difference between the pValue and FDR calculations, and in what circumstances use of the FDR is appropriate – the testing of an entire sub/collection, but not individual gene sets or extremely small groups of sets. Perhaps we can consider setting a lower bound on Gene Set database size below which we don’t report these scores, but determining where to draw that line isn’t mathematically clear cut.

 

So, to get back to your original question:



“I want to test signatures in C2.ALL but I have also custom gene sets I wanted to test.

I give back NES and FDR as a result. But if you treated custom gene sets, one by one, FDR will be 0, so not very comparable with FDR coming from the run over C2.ALL.”

 

You have two options, you can test your independent sets separately an evaluate their enrichment solely on the basis of NES and NOM pValue, or you can add them to the C2:ALL dataset and also get a FDR that considers how likely they are likely to be ”false” discoveries (I think this is really more like a “non-unique” discovery) in the context of the entirety of C2. Neither approach is strictly correct or incorrect, they simply give you slightly different information. Considering the nature of C2 as our repository of curated experiments, I personally would probably do later and include them with the C2 test.
