Dear Peter,


I noticed that, when running tools that add files to existing ones (like adding an index to a bam file with samtools index), the new (tbi) file will be stored where the input was taken from.
This most of the time makes sense in order to reduce storage and avoid duplication but what can I do when I want to duplicate the input and add the index to the copy in a new job folder?


My first solution was to make a parser that copies the input.file first and then operates on the copy (inspired by some of Guy's code)
<Feature-Req?> Would it be possible to add a flag/option <copy-input(s)> in the module maker to make to input data copied (duplicated) first in the new job folder then the copy used as input?



Another fix I found when some executable takes an 'output.file' parameter was to tweak it to save under: .../GenePatternServer/jobResults/<job_id>/<output.file>
In order to streamline this I created a  <job_dir> entry to point to ".../GenePatternServer/jobResults" in resources/custom.properties.
Did this <job_dir> alias already exist like <job_id> does and if yes would you have a full list of ALL default aliases or are they all to be found in "resources/custom.properties"? (from your previous post, more aliases have meanwhile be created in later versions). A manual page with such up-to-date info would be great!


Making daily progresses ... this starts to rock


Thanks
Stephane
