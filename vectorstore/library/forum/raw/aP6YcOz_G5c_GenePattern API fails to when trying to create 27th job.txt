Dave,


This is intended behavior.  The nominal limit is 25 concurrent jobs but due to multi-threading the exact cut-off is usually 1-2 higher if you are sending jobs in with a script.  This was implemented a while back when some user scripts were sending 300+ jobs all at once.  This had the effect of blocking out all other GenePattern users (we do have a compute limit) for several hours and occasionally crashed the server due to file transfer loads (we have a fix for this in beta).


If you modify your scripts to keep only ~20 running at a time you should still be able to get all your jobs through, if slightly more slowly.


Hope this helps


Ted
