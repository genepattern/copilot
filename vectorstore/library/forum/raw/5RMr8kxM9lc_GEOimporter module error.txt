I took deeper look at the issue here because it didn’t quite line up with what we’d expect from the FTP credentials issue. It appears to me that the SOFT file for the subseries accession that you’re trying to access doesn’t actually contain all the individual sample-level information that is expected in a soft file. I’m not sure if this is a general problem with sub-series accessions or if the submitter to GEO made a mistake/formatting choice that isn’t in line with our expectations. That said, this information is present in the super-series accession: GSE12094. If you run GEOImporter on this accession it will retrieve all data for the experiment including the samples you’re interested in and the other samples you’re not interested in.

I’ve run that and made the job result available here: https://cloud.genepattern.org/gp/pages/index.jsf?jobid=333192

 

Since this isn’t quite what you were wanting, I downloaded the resulting GCT and was able to extract the columns you were interested in and replace the “null” values with blank cells (required for use with GSEA). That processed GCT is attached here.

Hi Aracelly

 

GSE12168 is not an independent study, it is part of the GSE12094 super-series. You can see this if you go to the experiment’s pages on GEO. As I explained in the previous message, only the super-series contains all of the information needed to construct the expression file using GEOImporter. So, in order to build a GCT for GSE12168 you have to retrieve all the data in the parent study, GSE12094 and then manually extract only the parts that are needed. That is what I did to construct the GSE12168.gct file. It looks like that attachment may have been stripped from the previous email so I’m including it again here.
