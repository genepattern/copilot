Hi Stephane, 


There are two options here.


What language is your module in?  (This will help to answer option 1)


Option 2 is to configure GenePattern to only show "ERR" for a non-zero exit code.


To do this set "job.error_status.exit_value: true"  in config.yaml and set "job.error_status.stderr: false"

Hi Stephane, 


This thread also contains some excellent requests which we will investigate adding to GenePattern.


Notes:

>"adding multi-command syntax, testing and decision (if,else) within module maker command text box; allowing for instance some bash syntax with ‘;’ and pipes would do (i know you are concerned with hacker injecting code ;-)"
I think Peter has addressed this, but we probably won't change this in the near future as it would require a rewrite of our execution engine. It's not impossible, but it's also not insignificant. That's not to say that we won't do it, but we have other work that needs that sort of effort right now.


>"more control on the output like redirection of stderr and stdout to separate files (or together)"
This one is harder, as what gets sent to stderr vs stdout is mostly up to the module, and it's hard for us to generalize from module to module, but we can look into it. What we are actually planning to do is to set GenePattern to only ERR on non zero exit codes, by default. Therefore the contents of stderr & stdout would be informational, rather than determining the state of the job.
