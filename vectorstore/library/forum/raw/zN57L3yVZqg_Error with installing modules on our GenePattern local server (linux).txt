Some of our older modules fail to install from the repository. Please ignore any errors for modules that you do not plan on running.


For the modules that you do need to install, Linux servers require additional configuration steps. Usually this is as simple as defining a substitution variable; for example <perl>. In some cases you must first install the required software then define a substitution variable; for example <R2.15_Rscript>.


For perl, go to the Admin > Server Settings > Custom properties page and set the path to perl. It *can* be as simple as,

  perl=perl


See our documentation for more details on substitution variables:
  http://software.broadinstitute.org/cancer/software/genepattern/programmers-guide#_Writing_Modules_for_GenePattern


For additional details, if you are interested in reverse engineering, look at the readme in the resources/wrapper_scripts directory of your GP server installation.


I am happy to provide more detailed assistance as needed.

To correct these errors, you must set the <java> command substitution. Similar to what you did for perl, go to Server Settings > custom and set java. It can be as simple as:
  java=java

I recommend setting it to an explicit location, e.g.
  java=/usr/java/jdk_1.7.0-71/bin/java

Best practice is to set two substitution variables and use java_1.7 as the default e.g.
  java_1.7=/usr/java/jdk_1.7.0-71/bin/java
  java_1.8=/usr/java/jdk1.8.0_121/bin/java
  java=<java_1.7>
Most of our <java> modules were developed and testing with java_1.7. Newer modules may require java_1.8.

If you only have one version of java, I recommend  java_1.8.

The <java> fix will correct two types of installation errors that you are seeing:
1) "no substitution available for <java>", for ListFiles
2) "IOException while running patch: Cannot run program "-Dant.home=...""
  This obscure message is because the builtin <ant-1.8> command requires <java>

The TopHat error requires further investigation on your part. Make sure to set the correct path to perl for your server.
