Our current best practice is to run modules in docker containers. As a matter of fact, docker is required on the new public GenePattern Server running in the cloud. See this blog post for general information on the migration to the cloud:
    http://software.broadinstitute.org/cancer/software/genepattern/blog/2018/10/25/genepattern-is-moving-to-the-cloud


This means that the "Programming Language" page is no longer relevant. Our developer documentation and admin pages are not yet up to date. We have been mostly focusing our attention on the end users. I suggest starting with a 3.9.11 release candidate. This comes out-of-the-box configured for docker integration. A few additional steps are required, depending on which module and which OS you are using.


The release candidates are available for download from GitHub ...

    https://github.com/genepattern/genepattern-server/releases


At the moment (circa Jan 2019), you should start with the 3.9.11 Pre-release version of GenePattern. The Mac OS X installer is preconfigured to run modules with docker. The linux version requires additional configuration. Go ahead and run the installer on your system.

Note: Running modules in docker from the Linux GP server is not quite ready for public use. We have been putting all of our effort towards supporting this on the cloud.gp server which is running on AWS infrastructure. In February we will test this and write up README style documentation.


Meanwhile, if you want to get started right now, I recommend ...
* install GenePattern on your Linux server
* install docker
* verify that you can run docker from the linux command line
* make a custom configuration file for your server, e.g.
cd /path/to/gp/resources
cp config_default.yaml config_custom.yaml

* restart your server

* reverse engineer the Mac OS X installation, edit the './resources/config_custom.yaml'

to GenePattern Help Forum
I have not yet gone through the exercise of configuring a linux installation to run modules in docker. The Mac and Linux installer are configured to work with Docker, but we have not done any testing with the linux installer. 


The easiest thing to do is to wait for the official 3.9.11 release of GenePattern. I hope to have something ready for review in early February. If you want to get started right away ...


* first, install docker on your server, make sure you can run basic docker commands from the command line
* then start with the linux installer


After you run the installer you have have to set the path to docker. First make a copy of the 'config_default.yaml'  as 'config_custom.yaml'. Then edit the config_custom.yaml file. If necessary, change the path to where you installed docker. Here's the default value:



            "docker": "/usr/local/bin/docker"


Then restart the server. 


To test your installation, install the ConvertLineEndings module and run a test job.

to genepatt...@googlegroups.com
GenePattern now runs modules in docker containers. We removed the "Programming Language" page because it does not allow you to select the docker image to use. Instead you must set the 'job.docker.image' in the manifest file. You should also replace the substitution variable ('<R2.5>') with the executable that you want to run in your container ('R').
 
To fix your error ...

* (optional) add 'R2.5' as a custom property.
Go to the "Administration > Server Settings > Custom" page and add a new "R2.5" custom setting.
  R2.5=R

* set the 'job.docker.image' for your module to use an R/2.5 docker container
Create a new version of your module and edit the manifest file. Update the lsid version, add the job.docker.image, and (optionally) edit the commandLine. For example:
old version:

urn:lsid:my-example:cancer.software.genepattern.module.analysis:00062:2.2
commandLine=<R2.5> --version

new version:

urn:lsid:my-example:cancer.software.genepattern.module.analysis:00062:2.3
job.docker.image=genepattern/docker-r-2-5
commandLine=R --version

Create a new zip file with the updated manifest file. Install the module from the new zip file.

For testing, try these commands from your shell.

# verify that docker is on your path
$ which docker
# verify the docker version
$ docker --version
# run the R --version command in the 'genepattern/docker-r-2-5:0.1' container.
$ docker run -it genepattern/docker-r-2-5:0.1 R --version


FYI, technically, you can still run a legacy module on your server, e.g. something with the '<R2.5>' substitution on the command line. However, these modules will not be portable and we will not be able to support them on the public GenePattern Server.

Regards,
Peter

to GenePattern Help Forum
The config file is set up for Mac OS X; it requires additional edits to work on a Linux system. Change the 'job.docker.bind_src' and 'job.docker.bind_dst' parameters in your config_custom.yaml file.
Example:
            "job.docker.bind_src": "/opt/genepattern"
            "job.docker.bind_dst": "/opt/genepattern"
This file path is mounted into the docker container for each running GenePattern job.


Look for more detailed documentation in the "Docker integration" section of the config file.
Make sure to reload the config file.
From "Administration > Server Settings > Job Configuration", click "Reload Job Configuration".
If for some reason you had a typo, you will see an error message on the page.


Regards,
Peter

It looks like you are trying to run a legacy '<R2.5>' module, which actually wraps the call to R via a java class. We have a container for this. I have a demo module in the works. As a sneak peek, here are the relevant entries from the manifest file:

job.docker.image=genepattern/docker-r-2-5:0.1
commandLine=<java> -DR_HOME=/usr/local/lib64/R "-Dr_flags=--no-save --quiet --slave --no-restore" -cp /build RunR <libdir>hello.R hello

The <libdir> is mounted into the docker container.
