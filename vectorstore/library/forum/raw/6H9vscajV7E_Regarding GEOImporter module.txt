Hi Niharika,

 

For Job 329941: The issue here is that the dataset you’re inputing the GEO ID for is an RNA-seq dataset where the count information has been deposited in a separate file:
https://ftp.ncbi.nlm.nih.gov/geo/series/GSE126nnn/GSE126101/suppl/GSE126101%5Fcounts%2Ecsv%2Egz

And not in the SOFT/Series Matrix files that are used by the GEO Importer tool. At some point it became convention for people to deposit RNA-seq data into GEO with these separate files rather than using the soft file. Unfortunately, this means that the GEO Importer tool only really works with deposited microarray data that follow the proper.

 

If you’re intending to run GSEA on this data you would need to download the _counts.csv file and convert it into a GCT (excel should work for this). I’ve taken the liberty of doing this for you and will be attaching the file to a separate message. With this file you can normalize the counts using the GenePattern DESeq2 module. DESeq2 should give you a “normalized_counts.GCT” file that can be used with GSEA (this file will also be attached to the follow-up email). For GSEA you’ll want to set collapse/dataset to collapse, and use the Human_Ensembl_Gene_ID CHIP file. You’ll also need a CLS file, I’ll also include one of those, but you might want to adjust it some for your specific interest here – in the one I’m including I’ve combined the P5 and P6 timepoint since otherwise there are only 2 samples per treatment group. GSEA has difficulty with N=2 experiments. You’re also going to need to set permutation type to gene_set instead of phenotyoe.

 

For Job 329462: The issue is that FTP credentials were incorrectly populated, probably by auto-fill into the ftp proxy username and ftp proxy passwords fields. Try rerunning this job and deleting the data that was filled in there.

 

For Job 329459: This is again the RNA-seq issue that was the problem for Job 329941, however, the processing here is going to be a little more complicated, I’ll get back to you on it.
