to genepatt...@googlegroups.com
Hello,


Looking at the files you sent they seem to be formatted correctly at this point, the only significant issue is that your gct file appears to only contain 4504 genes. GSEA expects the entire universe of all expressed genes which is typically on the order of tens of thousands of genes. Was this list pre-filtered in some way?

Additionally, if you're using MSigDB gene sets for your analysis, you'll want to enable the "Collapse" option and specify the chip file: Human_Gene_Symbol_with_Remapping_MSigDB.v2024.1.Hs.chip file from MSigDB to ensure that your gene symbols are matched properly.


If you're still having trouble after checking your collapse/chip settings, and addressing the issue with number of genes, please let me know

to genepatt...@googlegroups.com
Just to followup, I was able to run the two files you sent in the GSEA desktop application, with the Kegg_medicus collection without any issue. You will need to change the permutation type to "gene set" due to there only being three samples in one of the phenotypes. But it does appear to run without error on my end.



One little addendum to what I said before, you probably do want to remove rows with all zero counts, these genes aren't part of the expressed universe and they can have some small issue with GSEA's correction factors for low variance genes. Typically you'd use a threshold of 5 or 10 counts summed across all samples to set the expression floor.
