Hi,


there was an intermittent issue with the file rename operation where it failed sometimes.  In trying to get more information about the failures I changed the code to use a slightly different method that would give more details (switched from java.io.File rename() to java.nio.Files move() method for any who see this and are interested) and now its working without error for me every time.  The fix will be in the next release but i have pushed a new docker container that you can try without waiting.


Try running the script as before but provide the version tag "genepattern/genepattern-server:test_070121"  instead of using the default.


e.g.     ./start-genepattern.sh -v test_070121 


Please let me know if this works for you.


Ted

From what you say it seems likely that there is a file permissions issue with your local (host) tasklib directory such that the docker container cannot write to it.  By removing the volume mount GenePattern will simply use a folder inside the container that is not exposed on the host machine (ie your laptop).  This should run fine, however if you were to delete the container (or try to update to a newer version of the GenePattern container) your old installed modules would be lost.
