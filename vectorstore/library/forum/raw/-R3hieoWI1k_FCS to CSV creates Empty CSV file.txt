Hi guys,
I inspected the FCS file a binary editor and turns out that it is somewhat bad. Specifically, the FCS header says that the TEXT segment ends at the same byte position (3580) where the DATA segment starts; this is wrong, the output from your CyTOF is off by one byte with respect to where the TEXT segment ends, which confuses the FCS2CSV convertor (i.e., the FCS2CSV convertor does not know if byte 3580 is part of the TEXT segment or the DATA segment).


I fixed the FCS header to state the correct TEXT segment end offset (3579) and then I was able to run the convertor no problem. I shared the fixed FCS file as well as the output from the conversion here:
https://drive.google.com/open?id=0B7qA2XRMbgZAMGgxdjRkUENGSjA



I cannot commit to making the FCS2CSV convertor resistant to this sort of an file format issue at this point. If you have several corrupted files that you need to convert, then you could
1) Use FlowJo to read the FCS and export the CSV; FlowJo is much more liberal in terms of what file formats it tolerates. You could just sign up for a free 30 days trial if this is a one-time thing (disclaimer: I work for FlowJo)
2) Fix the FCS files manually in a binary editor (like iHex... but that would require you to understand the FCS spec a bit)
3) Convince Fluidigm that they should fix the output files
4) Use R and the flowCore library; it will complain, but it will read the file (and likely drop the last keyword due to this particular issue). So once you have read it using read.FCS then you should be able to save the data matrix using the write.csv function.
