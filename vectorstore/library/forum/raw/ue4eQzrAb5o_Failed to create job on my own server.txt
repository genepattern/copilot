Hi


sorry about that, it is the result of a bug that got out in the last release.  It has been fixed but we haven't built a new release since the fix.


The problem is that it expects for there to be job input parameters defined (i.e. the options lists  for memory and cpu choices) and they are not present by default.  You should be able to get around this by adding a jobInputParams.yaml file (example below) and then referencing that in your config_custom.yaml file.  Then reload the configuration or restart the server and try to run a job again.


So in your config_custom.yaml, add this line



        # custom drop-down menus on the job input form

         job.inputParams: "jobInputParams.yaml"



Then in your resources directory add the jobInputParams.yaml file.  Below is the content from the one on my laptop currently.  Realistically you probably don't want to give it options for RAM/CPU values that your server cannot satisfy.


Hope this helps, let me know if it does not,


Ted


=========.  jobInputParams.yaml ==========

{

  

    name: "Job Options",

    hidden: false,

    parameters: [

    { name: "job.memory",

      altName: "job.memory",

      choices: [ "=(default)", "1G", "2Gb", "4Gb", "8Gb", "16Gb", "32Gb", "64Gb", "128Gb", "256Gb"],

      defaultValue: "",

      optional: true

    },




    { name: "job.cpuCount",

    description: "optional --container-overrides vcpus=(job.cpuCount)",

    choices: [ "=(default)", "1", "2", "4", "8", "12", "16" ],

    defaultValue: "",

    optional: true

    },




    { name: "job.walltime",

    altName: "walltime",

    description: "the runtime limit for the job in {days-hh:mm:ss} format",

    choices: [ "=(default)", "00:00:02=debug (2 seconds)", "02:00:00=short (2 hours)", "04:00:00=long (4 hours)", "24:00:00=max (1 day)" ],

    defaultValue: "02:00:00",

    optional: true

    }

    ]

}
