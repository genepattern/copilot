Hello Angela, 


The initial errors you encountered were due to two factors.


1) In one job you specified both an accession id and a value for the soft file when the instructions are to provide one or the other
2) In that same job you specified a path to a directory for the soft file and not the soft file itself


I ran your job again with just the accession id and came up with a more informative error which indicates and issue that often comes up with GEOImporter as the data there does not
always match what the module requires. It could be that the data set contains some non-numeric values that prevent the module from completing. The only recourse would be to download the SOFT file and manually remove those values.

Kyle,


I looked at a couple of your jobs and in the stderr.txt files it said something like "Host EC2 (instance i-06376af584861a4dc) terminated.".  While there are several causes that could result in a message like this, due to the way that GenePattern delegates jobs through AWS batch we see this most frequently when a module crashes its container by running out of memory.  I re-ran one of your accession jobs and the soft job  with 16GB of memory (up from the 2GB default used in your jobs) and both completed successfully generating gct files.


So go ahead and re-run your job with more memory and you should be fine.  16GB certainly worked but you might be able to get away with less.


Hope this helps,


Ted
