Dave


this is due to a bug in our server, one that we had found recently and hope to get deployed to prod in a week or two.  There is a workaround you can try (it works for me in a simpler test case).


The issue is when the advanced job options (cpu, memory etc) do not exactly match the values provided by the server for the module.  In this case you are asking for "4 Gb" of memory, but the value in the settings ins "4GB" without the space.  Try changing the setting of the "job_memory" variable at the top of your notebook to remove the space and retry it.


if it still fails, you may have to wait a week or two to be able to run this programmatically.  You should be able to still run jobs in the meantime via the UI though this might be a bit cumbersome.


Let me know if this works for you,


Ted
