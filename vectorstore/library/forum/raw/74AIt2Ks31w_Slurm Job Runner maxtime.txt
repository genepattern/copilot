Yes this is possible.  The best practice is to use the 'job.walltime' configuration property.

What version of GP are you using, and what SLURM integration code are you using? I have to look at the source code and/or check with Thorin before I can provide a detailed answer for SLURM.

Read on for a general overview. This is a two part process.
  1) customize the job.walltime in the config_yaml file in d-hh:mm:ss format
  2) (if necessary) implement support for 'job.walltime' in your SLURM integration

Step 1: customize 'job.walltime'
---------------------------
# add entries by module name or full module lsid to the 'module.properties' section
module.properties:
    ConvertLineEndings:
        # set max walltime to 2 hours
        job.walltime: '0-02:00:00'
    TopHat:
        # set max walltime to 7 days
        job.walltime: '7-00:00:00'

The 'job.walltime' can be customized by user, by module, or as a global setting.
For testing, you can also customize by user and module. For example,

user.properties:
    my_user_id:
        module.properties:
            TopHat:
                # for debugging, kill tophat after 30 seconds, just to see what happens
                job.walltime: '0-00:00:30'

The 'job.walltime' can also be customized on a per-job basis, by adding a drop-down menu to the GUI. Let me know if you are interested. I will write up how to this. (You don't need to write any code).

Step 2: JobRunner API integration
---------------------------
  To set a maxtime for SLURM, you may need to modify the startJob method of the JobRunner API.

    public String startJob(final DrmJobSubmission job) throws CommandExecutorException {
        ...
        Walltime w=job.getWalltime();
        if (w != null) {
            System.out.println("walltime: "+w);
        }
        ...
     }

Use job.getWalltime() to get the custom walltime value for your job. It may be null if no value is supplied.
The Walltime class makes it easier to work with the user-supplied 'job.walltime' value. E.g.
        // convert to number of milliseconds
        w.asMillis();
        // format as 'hh:mm'
        w.formatHoursAndMinutes();
       
        //Format as the total number of minutes.
        // This is simply a convenience method for the direct call to the timeunit class:
        //   ""+w.getTimeUnit().toMinutes(w.getDuration());
        w.formatMinutes();

   source code links:
     https://github.com/genepattern/genepattern-server/blob/develop/src/org/genepattern/drm/Walltime.java
     https://github.com/genepattern/genepattern-server/blob/develop/src/org/genepattern/drm/JobRunner.java

Use the 'job.inputParams' configuration property to add a 'job.walltime' option to the GUI.  This is a two part process. Step 1, create a jobInputParams_yaml file. Step 2, update your config to include those params in the GUI.

To get started, save the attached 'jobInputParams_walltime.yaml' file to your ./resources folder and edit your config_yaml file, e.g.

default.properties:
    job.inputParams: jobInputParams_walltime.yaml

Don't forget to Admin > Server Settings > Job Configuration > Reload job Configuration after editing the config_yaml page.
Note: you do not have to reload the configuration after making edits to the jobInputParams_yaml file. These changes take place automatically. If there are any YAML typos (which there will be on your first try) the entire file is ignored.

The 'job.inputParams' is also configurable on a per-user, per-module basis. It's not uncommon for me to use more advanced options for admin-type users, e.g.
group.properties:
    administrators:
        job.inputParams: jobInputParams_admin.yml


This is can done for other JobRunner API options such as 'job.memory' and 'job.cpuCount'. Stay tuned, I'll pass along a fuller example

Peter

Additionally you can add 'job.walltime' directly to the manifest file
for a module. This becomes the default value on a server which does not
have custom entries in the config file.

Note: use '=' in the manifest file, use ':' in the config_yaml file. E.g.

In config_yaml ...
module.properties:
my-module:
# set max walltime to 1 day
job.walltime: '0-24:00:00'

In manifest file for 'my-module'
job.walltime=0-24:00:00
