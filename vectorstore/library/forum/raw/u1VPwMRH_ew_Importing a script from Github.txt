Hello,


There are several ways to might use a script on GitHub in your GenePattern Notebook project. If your script has a setup.py file, the easiest way may be to install it via pip. For example



    !pip install --user git+https://github.com/<orgaization>/<repo>.git


On the other hand, if your script is a single Python file, it may be easier to simply download it to your home directory. For example:


    !wget https://raw.githubusercontent.com/genepattern/genepattern-notebook/master/genepattern/remote_widgets.py



In either case, you will want to do a python import for the script after it is downloaded.

Here’s another way to fetch and run Python code …

 

Put the Python code in Github and then do this:

 

import requests

 

exec(requests.get(https://raw.githubusercontent.com/cytoscape/jupyter-bridge/master/client/p4c_init.py).text)

 

 

This is different from %load because it executes the code directly and executes it, whereas %load only copies the code into the cell so you can re-execute the cell with the imported code inside of it.

 

Pros and cons … the pro is obvious … it’s essentially an injection of Github-resident code into current execution thread. The con is that one never knows quite what’s in that Github code, so it has to be trusted by whomever is using it.

 

In our case, we’re using it as initialization code for py4cytoscape (https://py4cytoscape.readthedocs.io/en/latest/). We’re recommending the code snippet to users who don’t what to know or care how this initialization is actually done. There’s nothing to stop a user from copy/pasting the Github code into their own cell if they don’t want to rely on or trust the Github version.

 

On the other hand, if we improve the Github-based initialization code, we can improve it for all users instantly by checking in the new version.

 

One perc … note that this initialization code checks for certain variables being already defined, and if they are, the variables’ values are used instead of the initialization code’s defaults. This is a way of parameterizing the initialization … this is useful here for selecting the exact py4cytoscape module to load and to set up debugging flags.

 

I suspect the same approach would work for R, but that’s another adventure.
