Hi Krystine,

 

I dug into your dataset here and I think I identified the issue. In your input data file “Model_Archer_red.unique.gct” pretty much all the values seem to be between -10 and 10, but in your preprocessing parameters file you’ve specified the following parameters:

 

thres = 20

ceil = 100000

fold = 5

delta = 500

norm = 6

 

This applies a series of thresholds using a variation filter function to the dataset: a min value threshold of 20, a min fold change threshold of 5, and a delta threshold of 500. After applying these parameters there are simply no genes left in the model. Since so much of your data is negative values, the threshold is setting basically everything to “20” causing the rest of the thresholds to screen it all out. The fold and delta are also not fitting the data well since the distribution is largely between -10 and 10, the delta 500, fold 5 aren’t fitting the data.

 

I would encourage you do perhaps generate some histograms of your dataset (or at least eyeball the data for “typical” values) to try to pick filter parameters that better fit the distribution being observed, similarly for the

Test_CCTMS_ data, which seems to have a substantially different distribution than the Model data (which isn’t a problem per-se, it just has to be accounted for the variance filter thresholds).

 

Let me know if you have other questions and I’ll try to answer as best as I can

Hi Krystine,

 

I agree, the documentation for these parameters could be improved. Here’s what’s happening from looking at the module code:

 

Threshold: Applied as the minimum floor value to the dataset (either model or test depending on which preprocessing file). Values below this value in the applicable dataset will be set to this value – since the assumed input is gene counts/microarray intensities it doesn’t apply this value on an absolute value basis separately to negative and positive distributions, it just applies it as a blanket floor. You can omit this entry from the txt file to not perform this filtering.

 

Ceil: Applied as a maximum ceiling value to the dataset (either model or test depending on which preprocessing file). Values above this value in the applicable dataset will be set to this value. You can omit this entry from the txt file to not perform this filtering.

 

Fold and Delta: These are used as minimum variation filters applied to each row of the dataset. They are calculated on each row (gene) using the row maximum and the row minimum. Fold change is calculated row.max /row.min, and the Delta is calculated from row.max - row.min. Importantly, this is performed after applying the threshold and ceiling. A row is accepted if both the calculated row fold is and a row is accepted if this is >= fold parameter and the row delta is >= delta parameter. If either fold or delta are omitted from the text file both fold and delta filtering will not be performed.

 

There is another parameter described in the code “shift” which allows applying a global constant to correct for a known offset (this was likely implemented to correct microarray data for example if one dataset was reading a higher global background intensity than the other). Shift is applied after performing the Thresholds and Ceiling calculations, but before the Fold and Delta variance filter.

 

Let me know if you have any questions about my descriptions here

Hi Krystine,

 

I think I found the issue, I misinterpreted a bit of the parsing code.

What happens is if you omit the values entirely the program inserts the logical value NULL, but later it tests for the string value “NULL”, these aren’t the same and in R the tests return different results. In order to trigger the skipping of these filtering steps properly, you actually have to put

 

thres = "NULL"

ceil = "NULL"

 

etc. for the other parameters, with NULL in quotes, in your preprocessing text file.

Sorry about that!

 

-Anthony
